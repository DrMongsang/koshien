# 🚨 緊急対応マニュアル - データ消失対応

## ⚠️ 現在の状況

- **症状**: 過去データ（11月など）が「予約履歴_蓄積」シートから消失
- **原因**: 旧バージョンのコードが5分ごとに自動実行され、過去データを削除している可能性
- **緊急度**: 🔴 最高（今すぐ対応が必要）

---

## 🛑 Step 1: トリガーを今すぐ停止（最優先）

**これ以上のデータ消失を防ぐため、必ず最初に実行してください。**

### 方法A: メニューから停止（推奨）

1. スプレッドシートを開く
2. メニューバーに「🚨緊急対応」があれば、それをクリック
3. **「🛑 全トリガーを停止」**を選択
4. 確認ダイアログが出たらOK

### 方法B: GASエディタから停止

1. **ツール → スクリプトエディタ**を開く
2. 左側のメニューで**「トリガー」**（時計アイコン⏰）をクリック
3. 表示される全てのトリガーの右側の**「︙」**をクリック
4. **「削除」**をクリック
5. 全てのトリガーを削除する

### 確認方法

トリガーが0個になったことを確認：
- GASエディタの「トリガー」画面に何も表示されない
- または「🚨緊急対応」→「⚙️ トリガー状態を確認」で確認

---

## 💾 Step 2: 変更履歴からデータを復元

### 2-1. 変更履歴を開く

1. スプレッドシートで**ファイル → 変更履歴 → 変更履歴を表示**
2. 右側にパネルが開く

### 2-2. 復元ポイントを探す

**探すべき版の特徴：**

- ✅ **12月9日より前**の版（できれば12月上旬）
- ✅ **行数が多い**版（現在より明らかに多い）
- ✅ **「予約履歴_蓄積」シートに変更**がある版
- ✅ 11月のデータが含まれている版

**確認方法：**

1. 変更履歴の版をクリック
2. 「予約履歴_蓄積」シートを開く
3. スクロールして11月のデータがあるか確認
4. データ件数を確認（画面右下に表示される行数）

### 2-3. 復元を実行

1. 11月データがある版を見つけたら、その版をクリック
2. 内容を再度確認
3. 画面上部の**「この版を復元」**ボタンをクリック
4. 確認ダイアログで**「復元」**をクリック

### 2-4. 復元後の確認

1. 「予約履歴_蓄積」シートを開く
2. 11月のデータがあることを確認
3. データ件数を確認
4. **すぐに次のステップへ進む**（放置すると再度消える可能性あり）

---

## 🔧 Step 3: 緊急対応版のコードを適用

データ復元後、**必ず**緊急対応版のコードに切り替えてください。

### 3-1. GASエディタを開く

1. **ツール → スクリプトエディタ**を開く
2. 既存のコード（コード.gs）を開く

### 3-2. コードを置き換え

1. 既存のコードを**全て選択**（Ctrl+A / ⌘+A）
2. **削除**
3. `gas/予約履歴システム_緊急対応版.gs` の内容を**コピー**
4. **ペースト**
5. **保存**（Ctrl+S / ⌘+S）

### 3-3. テスト実行

1. メニューバーに**「🚨緊急対応」**が表示されることを確認
2. 「🚨緊急対応」→「📊 現在のデータ状況を確認」を実行
3. 月別のデータ件数が表示されることを確認
4. 11月のデータが表示されることを確認

---

## 📊 Step 4: データ診断

### 診断の実行

1. 「🚨緊急対応」→「📊 現在のデータ状況を確認」を実行
2. 以下の情報を確認：
   - 総データ件数
   - 月別データ件数
   - 警告メッセージ

### 正常な状態の例

```
📊 データ診断結果

総データ件数: 1,234件

【月別データ件数】
2024-10: 150件
2024-11: 450件
2024-12: 634件
```

### 異常な状態の例

```
📊 データ診断結果

総データ件数: 634件

【月別データ件数】
2024-12: 634件

【警告】
⚠️ 2024年11月のデータが0件です
→ 変更履歴から復元してください。
```

**異常な場合**: Step 2に戻って再度復元してください。

---

## 💾 Step 5: 緊急バックアップの作成

データが正常に復元できたら、**今すぐバックアップ**を作成してください。

### バックアップ作成

1. 「🚨緊急対応」→「💾 今すぐバックアップ作成」を実行
2. バックアップシートが作成される
3. シート名（例：`緊急バックアップ_20241214_153000`）を確認

### バックアップの確認

1. シート一覧から作成されたバックアップシートを開く
2. データがコピーされていることを確認
3. **このシートは絶対に削除しないでください**

---

## 🔍 Step 6: 根本原因の調査

### 確認すべきこと

#### 1. どのバージョンのコードが動いていたか？

GASエディタで以下を確認：

**旧バージョンの特徴：**
```javascript
function inDateWindow(d) {
  const range = 7 * 24 * 60 * 60 * 1000; // 7日間の窓
  return d >= new Date(now - range) && ...
}
```

**修正版の特徴：**
```javascript
function inDateWindow(d) {
  // 全データを保持するため、常にtrueを返す
  return true;
}
```

#### 2. トリガーがいつ設定されたか？

- GASエディタの「実行数」（再生ボタンアイコン）をクリック
- 過去の実行履歴を確認
- 5分ごとに実行されていたか？

#### 3. いつからデータが消え始めたか？

変更履歴で確認：
- データ件数が減少し始めた時点
- 最後に正常だった時点

---

## ⚙️ Step 7: ライブラリのデプロイ（11店舗共通の場合）

**このスクリプトがライブラリとしてデプロイされている場合のみ：**

### 7-1. 緊急対応版をデプロイ

1. GASエディタで**デプロイ → デプロイを管理**
2. 編集（✏️）をクリック
3. バージョンを「**新バージョン**」に変更
4. 説明：「緊急対応版: データ削除機能を無効化」
5. **デプロイ**をクリック

### 7-2. 各店舗で更新

**重要**: 11店舗全てで以下を実行してください：

1. 各店舗のスプレッドシートを開く
2. ツール → スクリプトエディタ
3. 左側の「ライブラリ +」
4. 該当ライブラリの右側の更新マーク をクリック
5. **最新バージョン**を選択
6. 保存

---

## 🚨 今後の運用（緊急対応期間中）

### やるべきこと

- ✅ **毎日1回**: 「📊 現在のデータ状況を確認」を実行
- ✅ **データ追加前**: 「💾 今すぐバックアップ作成」を実行
- ✅ **週1回**: 変更履歴を確認してデータが減っていないかチェック

### やってはいけないこと

- ❌ トリガーを再設定しない（自動実行は停止したまま）
- ❌ 旧バージョンのコードに戻さない
- ❌ バックアップシートを削除しない
- ❌ 「予約履歴_蓄積」シートを手動で編集しない（特に削除）

---

## 🔄 正式版への移行（復旧完了後）

緊急対応版でデータが安定したら、正式な修正版に移行してください。

### 移行のタイミング

以下の条件を全て満たしたら：

- ✅ データ復元が完了し、11月のデータがある
- ✅ 1週間以上データが消失していない
- ✅ バックアップが複数作成されている
- ✅ 根本原因が特定できている

### 移行手順

1. `gas/予約履歴システム_修正版.gs` に切り替え
2. テスト実行
3. ライブラリを新バージョンでデプロイ
4. 各店舗で更新
5. トリガーを再設定（慎重に）

詳細は `gas/データ復旧手順.md` を参照してください。

## 📞 エスカレーション

### 以下の場合は至急連絡してください

- ❌ 変更履歴からも11月データが見つからない
- ❌ 復元してもすぐにデータが消える
- ❌ エラーが発生して復元できない
- ❌ トリガーが停止できない

### 連絡時に必要な情報

1. 現在のデータ診断結果（スクリーンショット）
2. トリガー状態（スクリーンショット）
3. GASエディタの実行ログ
4. いつからデータが消えたか
5. これまでに行った操作
